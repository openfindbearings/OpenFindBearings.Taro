# Taro 跨端适配说明 v1.2.0

## 概述

Taro 项目一套代码编译到多平台（H5、微信小程序、Android/iOS RN），各平台存在差异。本文档说明跨端适配策略与平台特定处理。

> **当前阶段：只做 RN（Android/iOS），按标准 RN 实现。** H5、微信小程序是后续第 2、3 阶段，届时在 RN 基础上"做加法"。本文档中 H5/小程序条目为规划，未实现。

## 变更日志

### v1.2.0 (2026-09-08)

- `getBaseUrl` 实际按 `process.env.TARO_ENV === 'h5'` 分支（非 `isH5()`）；RN/小程序必须返回绝对地址，否则真机相对路径请求 `Network request failed`。
- Hermes(RN 0.70) 无 `URLSearchParams.set` → 手写 `buildQuery`（`config.ts`）。
- API 图片字段可能是相对路径 `/images/...`，RN `<Image>` 加载会告警/破图 → `usableImage()` 仅放行绝对 http 地址，否则回退占位图标。
- `Icon` 的 `toPascal` 需同时按 `-` 与 `_` 分割，否则连字符图标名（trending-up/user-plus/badge-check）解析不到 Lucide 导出。
- `navigationStyle:'custom'` 提升到 `app.config.ts` 的 `window` 全局，避免新增页面漏配 `.config.ts` 又冒出原生顶栏。
- 记录 `border-*-style` 在 RN 无效（stylelint 告警，RN 默认实线不受影响，但 H5 需它才画线 → 跨端分隔线推荐独立 1px View）。

### v1.1.0 (2026-09-07)

- 明确三阶段路线：本轮纯 RN，`scalable:false` + `deviceRatio` 只作用 RN 编译链。
- 图标：RN 用 `lucide-react-native`+`react-native-svg`，`lucide-react-taro` 已卸载。
- 存储：RN 不支持同步 `getStorageSync`，异步封装。
- 安全区：`react-native-safe-area-context` 的 `useSafeAreaInsets`（标准做法）。
- TabBar 切 tab 用 `redirectTo`（浮动自绘底栏）。

### v1.0.0 (2026-09-01)

- 初始版本。

## 三阶段路线

| 阶段 | 目标 | 状态 |
|------|------|------|
| 1 | 标准 RN（Android/iOS）：dp 直写度量、安全区、组件、主题 | **本轮** |
| 2 | 扩展 H5：CSS 变量运行时主题、rem 缩放、响应式 | 后续 |
| 3 | 扩展微信小程序：rpx、原生/浮动 tabBar、包大小 | 后续 |

原则：RN 限制最多，先攻克 RN，H5/小程序在 RN 基础上追加能力，不回迁 RN 去迁就 H5。

## 度量适配（核心）

| 平台 | 缩放机制 | 写码方式 |
|------|----------|----------|
| RN | `scalable:false` + `deviceRatio:{750:2}` 关两级缩放 | SCSS 写目标 dp（`44px`→44dp），所见即所得 |
| H5 | 默认 rem（`designWidth:750`） | 同 SCSS，运行时 rem 缩放 |
| 小程序 | 默认 rpx | 同 SCSS，运行时 rpx 缩放 |

> `config.rn.postcss` 双开关只在 RN 编译链生效，H5/小程序不受影响。

## 平台差异

| 能力 | RN（本轮） | H5（后续） | 微信小程序（后续） |
|------|-----------|-----------|-------------------|
| HTTP 请求 | Taro.request | Taro.request | Taro.request |
| URLSearchParams | 无 `.set`（Hermes）→ buildQuery | 支持 | 支持 |
| 本地存储 | AsyncStorage（异步） | localStorage | wx storage |
| 页面路由 | React Navigation | history | 小程序路由栈 |
| SVG 图标 | react-native-svg | 原生 SVG | 受限（Data URL） |
| 安全区 | useSafeAreaInsets | env(safe-area-inset) | 自动 |
| 渐变 | LinearGradient 组件 | CSS linear-gradient | 不支持 |
| gap | 不支持→margin | 支持 | 支持 |
| position fixed/sticky | 不支持→flex | 支持 | 支持 |
| border-*-style | 无效（默认实线） | 需它才画线 | 需它才画线 |

## 条件编译与平台分支

### 编译期判定

```typescript
import { isRN, isH5, isWeapp } from '@/utils/platform'  // 基于 Taro.getEnv()
// getBaseUrl 用编译期常量 process.env.TARO_ENV（见下）
```

### 文件级平台分支（推荐）

Taro RN 的 Metro resolver 优先解析 `.rn.tsx`，H5/小程序解析 `.tsx`。Icon、Switch、use-safe-area、use-system-theme 均此模式：

```
components/Icon/  index.rn.tsx (lucide-react-native) / index.tsx (lucide-react)
components/Switch/ index.rn.tsx (原生 Switch) / index.tsx (Taro Switch)
```

> `// #ifdef H5` 只对 JS 生效，Metro 不处理 SCSS 里的 #ifdef，也不影响 `.rn.tsx` 解析。SCSS 平台差异靠"只写 RN 兼容子集"。

## 存储适配

RN 不支持 `Taro.getStorageSync`，统一用 `src/utils/storage.ts` 异步封装（`getItem/setItem/getObject/setObject`）。

**Token 安全策略**：access_token 内存、refresh_token 本地存储、device_id 本地存储（登录绑定+刷新校验）。

## 安全区适配

RN 用 `react-native-safe-area-context`：`app.rn.tsx` 根包 `<SafeAreaProvider>`，NavBar/CustomTabBar 用 `useSafeAreaInsets()` 吃 insets，跨端 hook `use-safe-area`（`.rn.ts`/`.h5.ts`）。不手算"总高=基准+状态栏"。

## 网络请求

```typescript
// src/services/config.ts
const BFF_PROD_BASE = 'https://bff.515813.xyz'
export function getBaseUrl(): string {
  if (process.env.TARO_ENV === 'h5') return ''            // H5：相对路径 + dev proxy
  return process.env.TARO_APP_BFF_BASE_URL || BFF_PROD_BASE // RN/小程序：绝对地址
}
```

- **RN 真机/模拟器无 dev proxy，base 必须绝对地址**，否则 `Taro.request({url:'/mobile/...'})` 无 host → `Network request failed`。
- 查询串用 `buildQuery`（Hermes 无 `URLSearchParams.set`）。
- 图片用 `usableImage`：仅绝对 `http(s)` 地址渲染 `<Image>`，相对路径回退占位图标（API 的 image2DUrl/logoUrl 常为 `/images/...` 相对路径）。
- 统一走 Mobile BFF（`bff.515813.xyz/mobile/*`），不直连 API。

## 图标适配

| 平台 | 库 | 说明 |
|------|-----|------|
| RN | `lucide-react-native` + `react-native-svg` | 原生 SVG，`index.rn.tsx` |
| H5 | `lucide-react` | Web SVG，`index.tsx`（后续） |
| 小程序 | 暂 `lucide-react`，第三步评估 | 后续 |

统一经 `components/Icon` 抽象层。`Icon` 的 `toPascal` 同时按 `-` 与 `_` 分割（`trending-up`→`TrendingUp`），否则连字符名解析不到导出。`lucide-react-taro` 已卸载（与 RN 0.70 不兼容）。

## 路由与 TabBar

- **`navigationStyle:'custom'` 在 `app.config.ts` 的 `window` 全局设置**（全站自定义 NavBar，统一关 RN 原生顶栏），避免新增页面漏配 `.config.ts` 又冒出原生栏；各页 `.config.ts` 仍保留 `disableScroll:true`。
- TabBar 浮动自绘（`CustomTabBar`），切 tab 用 `Taro.redirectTo`（不用原生 tabBar）。

## 分隔线（border-*-style）

RN 不支持 `border-bottom-style`/`border-top-style`（stylelint 告警），但 RN 边框默认即实线，`border-*-width`+`border-*-color` 已能画线；H5/小程序则必须有 `border-*-style:solid` 才画线。跨端稳妥做法：**用独立 1px `<View>` + backgroundColor 作分隔线**（本轮已选此方案，逐处替换中）。

## 构建命令

| 平台 | 命令 | 产物 |
|------|------|------|
| RN 开发 | `pnpm run dev:rn`（Metro 8081） | 需 `adb reverse tcp:8081 tcp:8081` |
| RN 打 APK | `cd android; .\gradlew.bat app:installDebug` | debug APK |
| H5（后续） | `pnpm run build:h5` / `dev:h5` | dist/ |
| 小程序（后续） | `pnpm run build:weapp` / `dev:weapp` | dist/ |

> RN 改 SCSS 后必须重启 Metro（`--reset-cache`）；新增 `.config.ts`/原生库后需完整重启 + `gradlew clean` 重装 APK。

## 已知 RN 兼容坑（累计踩过）

- `lucide-react-taro` 与 RN 0.70 不兼容 → lucide-react-native。
- `getStorageSync` RN 不支持 → 异步封装。
- `Text` 的 `lineHeight`/`fontSize` 带 px 字符串崩溃 → 数值。
- 百分比 `border-radius` 崩溃 → `999px`。
- `position: fixed/sticky` 不支持 → flex + ScrollView。
- `gap` 不支持 → margin。
- className 文件作用域：跨文件用类名不生效 → 组件内部渲染（NavBar rightIcons）。
- `URLSearchParams.set` Hermes 未实现 → buildQuery。
- 相对图片地址 RN 加载告警/破图 → usableImage。
- 连字符图标名 toPascal 解析不到 → 按 `-`/`_` 分割。
- `getBaseUrl` 空串 → RN 真机 Network request failed → 绝对地址。
- Windows 下 `@tarojs/rn-runner` spawn EINVAL → patch `shell:true`。
- `react-native-safe-area-context` 需 4.x。
