## 背景与决策

App 设置项按性质分三类，分别落不同存储（已与用户确认）：

| 类别 | 项目 | 存储位置 | 状态 |
|---|---|---|---|
| 设备偏好 | 字体大小、主题色、深色模式、音效、震动 | 本地（AsyncStorage） | ✅ 已实现 |
| 账号偏好 | 首页模式（普通/简洁）、消息推送订阅 | 后端用户表 | ⏳ 待做（随登录） |
| 合规记录 | 隐私政策同意、注销申请 | 后端用户表（必须留痕） | ⏳ 待做（随登录） |

设备偏好换设备本应不同、且未登录也要能调，故留本地；账号/合规类需跨端一致或服务端消费，进库。进库依赖"当前登录用户"，因此**推迟到登录功能实现时一起做**。

## 隐私合规：主流做法（PIPL / 数据安全法 / 工信部）

**首次启动隐私政策弹窗**是行业标准（而非"登录即同意"）：
1. App 首次冷启动、**采集任何个人信息之前**，弹隐私政策/用户协议对话框，用户点"同意"后方可使用；"不同意"仅提供最小必要浏览或退出。
2. 同意记录**服务端留痕**：策略版本号 + 同意时间戳（UTC）+ 可关联用户/设备，满足 PIPL"同意可举证、可撤回"。
3. 政策更新后，新版本需再次征求同意（版本号变更触发重新弹窗）。
4. 提供撤回同意、查阅/更正/删除、注销入口（本 App 隐私管理页已列，操作入口随功能补齐）。

当前 Taro 已在设置页提供完整《隐私政策》《个人信息收集清单》《第三方信息共享清单》《隐私管理》《用户协议》全文（`src/content/legal.ts` + `pages/common/doc`），满足"告知"义务；"同意留痕 + 首次弹窗 + 撤回/注销后端"待登录功能时一并实现。
