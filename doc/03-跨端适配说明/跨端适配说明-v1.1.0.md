# Taro 跨端适配说明 v1.1.0

## 概述

Taro 项目一套代码编译到多平台（H5、微信小程序、Android/iOS RN），各平台存在差异。本文档说明跨端适配策略与平台特定处理。

> **当前阶段（v1.1.0）：只做 RN（Android/iOS），按标准 RN 实现。** H5、微信小程序是后续第 2、3 阶段，届时在 RN 基础上"做加法"。本文档中 H5/小程序条目为规划，未实现。

## 变更日志

### v1.1.0 (2026-09-07)

- 明确三阶段路线：本轮纯 RN，`scalable:false` + `deviceRatio` 只作用 RN 编译链，不影响 H5/小程序。
- 图标适配更新：RN 用 `lucide-react-native`+`react-native-svg`，`lucide-react-taro` 已卸载（与 RN 0.70 不兼容）。
- 存储适配：RN 不支持同步 `getStorageSync`，统一异步封装。
- 安全区适配：RN 用 `react-native-safe-area-context` 的 `useSafeAreaInsets`（标准做法），替代此前手算 `height=基准+状态栏` 的 hack。
- TabBar 切 tab 用 `redirectTo`（浮动自绘底栏，非原生 tabBar）。

### v1.0.0 (2026-09-01)

- 初始版本，平台差异、条件编译、存储适配、API 差异。

## 三阶段路线

| 阶段 | 目标 | 状态 |
|------|------|------|
| 1 | 标准 RN（Android/iOS）：dp 直写度量、安全区、组件、主题 | **本轮** |
| 2 | 扩展 H5：CSS 变量运行时主题、rem 缩放、响应式 | 后续 |
| 3 | 扩展微信小程序：rpx、原生/浮动 tabBar、包大小 | 后续 |

原则：RN 限制最多，先攻克 RN，H5/小程序在 RN 基础上追加能力，不回迁 RN 去迁就 H5。

## 度量适配（核心）

| 平台 | 缩放机制 | 写码方式 |
|------|----------|----------|
| RN | `scalable:false` + `deviceRatio:{750:2}` 关两级缩放 | SCSS 写目标 dp（`44px`→44dp），所见即所得 |
| H5 | 默认 rem（`designWidth:750`） | 同 SCSS，运行时 rem 缩放 |
| 小程序 | 默认 rpx | 同 SCSS，运行时 rpx 缩放 |

> `config.rn.postcss` 的双开关**只在 RN 编译链生效**，H5/小程序不受影响——这是本轮能"纯 RN 度量"而不破坏后续 H5 的关键。

## 平台差异

| 能力 | RN（本轮） | H5（后续） | 微信小程序（后续） |
|------|-----------|-----------|-------------------|
| HTTP 请求 | Taro.request | Taro.request | Taro.request |
| 本地存储 | AsyncStorage（异步） | localStorage | wx storage |
| 页面路由 | React Navigation | history | 小程序路由栈 |
| SVG 图标 | react-native-svg | 原生 SVG | 受限（Data URL） |
| 安全区 | useSafeAreaInsets | env(safe-area-inset) | 自动 |
| 渐变 | LinearGradient 组件 | CSS linear-gradient | 不支持 |
| gap | 不支持→margin | 支持 | 支持 |
| position fixed/sticky | 不支持→flex | 支持 | 支持 |

## 条件编译与平台分支

### 编译期判定

```typescript
import { isRN, isH5, isWeapp } from '@/utils/platform'  // 基于 Taro.getEnv()
```

> Metro dev 模式下 `process.env.TARO_ENV` 可能未注入，统一用 `Taro.getEnv()`（`utils/platform.ts`）。

### 文件级平台分支（推荐）

Taro RN 的 Metro resolver 优先解析 `.rn.tsx`，H5/小程序解析 `.tsx`。Icon 组件即此模式：

```
components/Icon/
  index.rn.tsx   // RN: lucide-react-native
  index.tsx      // H5/小程序: lucide-react
```

> 注意：`// #ifdef H5` 注释式条件编译只对 JS 生效，**Metro 不处理 SCSS 里的 #ifdef**，也不影响 `.rn.tsx` 解析。SCSS 平台差异靠"只写 RN 兼容子集"（禁 var()/渐变/gap/组合选择器）。

## 存储适配

RN 不支持 `Taro.getStorageSync`，统一用 `src/utils/storage.ts` 异步封装：

```typescript
import { getItem, setItem, getObject, setObject } from '@/utils/storage'
await getItem('merchant_approved')   // 返回 string | null
await setObject('app_settings', { simpleHome: true })
```

**Token 安全策略**：

| Token | 存储 | 理由 |
|-------|------|------|
| access_token | 内存 | 不持久化，防泄露 |
| refresh_token | 本地存储 | 持久化自动刷新 |
| device_id | 本地存储 | 登录绑定、刷新校验 |

## 安全区适配

RN 用 `react-native-safe-area-context`（标准库）：

- `app.rn.tsx` 根包 `<SafeAreaProvider>`。
- NavBar/CustomTabBar 用 `useSafeAreaInsets()` 取 `insets.top` / `insets.bottom`，外层 paddingTop/paddingBottom 吃内缩，内层固定基准高。
- 跨端 hook `src/utils/use-safe-area.ts`（`.rn.ts` 用 insets，`.ts` 其他端返回 0）。

> 不再手算"总高 = 基准高 + 状态栏"（旧 hack）。

## 网络请求

```typescript
function getBaseUrl(): string {
  if (isH5()) return ''   // H5 同源相对路径（webpack proxy）
  return process.env.TARO_APP_BFF_BASE_URL || 'https://bff.515813.xyz'
}
```

- H5 受 CORS 限制，BFF 配 AllowOrigin；RN/小程序不受 CORS 限制。
- 统一走 Mobile BFF（`bff.515813.xyz/mobile/*`），不直连 API。

## 图标适配

| 平台 | 库 | 说明 |
|------|-----|------|
| RN | `lucide-react-native` + `react-native-svg` | 原生 SVG，`index.rn.tsx` |
| H5 | `lucide-react` | Web SVG，`index.tsx`（后续） |
| 小程序 | 暂 `lucide-react`，第三步评估 | Data URL 或 iconfont（后续） |

统一经 `components/Icon` 抽象层，业务不直接 import lucide 包。`lucide-react-taro` 已卸载（v1.5.2 用 RN 0.71+ 的 codegenNativeCommands，与 Taro 3.6.40 的 RN 0.70 不兼容）。

## 路由与 TabBar

- 各页 `.config.ts`：`navigationStyle:'custom'`（去原生导航栏，用自定义 NavBar）+ `disableScroll:true`（滚动交 PageLayout）。
- TabBar 浮动自绘（`CustomTabBar`），切 tab 用 `Taro.redirectTo`（RN 端 `switchTab` 依赖原生 tabBar 配置，本项目不用原生 tabBar）。

## 构建命令

| 平台 | 命令 | 产物 |
|------|------|------|
| RN 开发 | `pnpm run dev:rn`（Metro 8081） | 需 `adb reverse tcp:8081 tcp:8081` |
| RN 打 APK | `cd android; .\gradlew.bat app:installDebug` | debug APK |
| H5（后续） | `pnpm run build:h5` / `dev:h5` | dist/ |
| 小程序（后续） | `pnpm run build:weapp` / `dev:weapp` | dist/ |

> RN 改动 SCSS 后必须**重启 Metro**（按 R/App reload 不重编 SCSS）；新增原生库（如 react-native-linear-gradient）后必须 `gradlew clean` + 重装 APK 才 autolink。

## 已知 RN 兼容坑（本轮踩过）

- `lucide-react-taro` 与 RN 0.70 不兼容 → 换 lucide-react-native。
- `getStorageSync` RN 不支持 → 异步封装。
- `Text` 的 `lineHeight`/`fontSize` 带 px 字符串崩溃 → 数值。
- 百分比 `border-radius` 崩溃 → `999px`。
- `position: fixed/sticky` 不支持 → flex + ScrollView。
- `gap` 不支持 → margin。
- className 文件作用域：跨文件用类名不生效 → 组件内部渲染（如 NavBar rightIcons）。
- Windows 下 `@tarojs/rn-runner` spawn EINVAL → patch `shell:true`。
- `react-native-safe-area-context` 需 4.x（5.x 不兼容 Gradle 7.5.1）。
