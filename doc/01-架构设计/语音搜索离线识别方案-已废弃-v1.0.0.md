# 语音搜索离线识别方案

- 版本：v1.0.0
- 状态：已实施（RN Android 端可用；H5/小程序入口提示"暂仅支持 App 端"）
- 适用范围：OpenFindBearings.Taro（RN Android）
- 变更记录：
  - v1.0.0 首次成文。

## 1. 背景与目标

移动端要为搜索框提供语音输入：按住说话识别轴承型号、品牌、类型或商家名称，识别文本直接进入现有搜索结果页。约束条件：

1. RN 版本锁定为 0.70（Taro 3.6.40 依赖，无法升级 Turbo Module 类库）。
2. 不对接后端云 ASR（现阶段无云账号、无后端接口）。
3. 国内 Android 真机普遍无 Google 服务（GMS），系统级 SpeechRecognizer 不可依赖。
4. 后续可能切换云 ASR，接入层必须可插拔，UI 零改动。

## 2. 技术选型

| 方案 | 兼容 RN 0.70 | 国内 Android | 结论 |
|---|---|---|---|
| react-native-vosk@0.3.3（旧 bridge） | 是 | 离线可用，不依赖 GMS | 选定 |
| react-native-vosk@2.x | 否，需 Turbo Module | 离线可用 | 弃（RN 版本不符） |
| @react-native-voice/voice | 是 | 需 GMS，国内失效 | 弃 |
| react-native-whisper 系列 | 否，JSI/Turbo | 离线可用、中文更准 | 弃（RN 0.70 不兼容，且工程量大） |
| 录音 + 后端云 ASR | 是 | 取决于云厂商 | 预留路线，本期不接 |

README 无关内容从略。关键取舍：Vosk 小模型中文对轴承型号（数字+字母混合）识别弱，属已知局限；通过 JS 后处理部分弥补格式问题（见 4.5）。

## 3. 总体架构

语音能力分三层，上层不感知底层引擎：

```
UI 层        VoicePanel（全屏原生 Modal，按住说话）/ 首页"讲语音"入口
逻辑层       hooks/useAsr（状态机 idle/recording/processing、误触取消、预热、兜底）
服务层       services/asr（AsrService 接口 + Vosk Provider 实现）
原生层       react-native-vosk@0.3.3 + assets/model-cn 模型
```

弹窗（隐私同意、语音面板、通用确认）统一为 RN 原生 Modal 自绘，规避 Taro showModal 在 Android 真机按钮触摸失效的缺陷。

## 4. 模块设计

### 4.1 服务抽象（src/services/asr/types.ts）

`AsrService` 接口：`isAvailable / load / start / stop / onResult / onError / dispose`。所有识别引擎（Vosk、未来云 ASR）实现该契约，调用方只依赖接口。

### 4.2 平台 Provider（asrProvider.ts / asrProvider.rn.tsx）

按 Taro 平台后缀文件模式：RN 端 Metro 解析 asrProvider.rn.tsx（Vosk 实现），H5/小程序解析 asrProvider.ts（占位，isAvailable=false）。入口 index.ts 以无后缀 import，两端各自命中，跨端构建不引 RN 原生库。

### 4.3 useAsr（hooks/useAsr.ts）

状态机与引擎生命周期：

- 状态：idle（空闲）/ recording（录音中）/ processing（停止后处理中）。
- startListening：注册事件监听后 start；start 为异步（含权限申请），期间若用户已松手，用 cancelledRef 标记，start 完成后补停，防残留录音。
- stopListening：置 processing、调 stop，兜底定时器 600ms（空录音 Vosk 不触发事件，超时按空结果复位）。
- cancelListening：误触取消入口，立即 stop 并复位 idle，不等结果、不回调。
- warmup：预热加载模型，与状态机解耦，打开语音面板时调用，使首次按住即可录音。
- 组件卸载时 dispose 引擎并清理监听。

### 4.4 VoicePanel（components/VoicePanel/index.rn.tsx）

全屏透明原生 Modal，中央 150dp 圆形大按钮：

- opened 时自动 warmup 预热模型。
- 按住（onPressIn）开始录音，按钮变"松开结束"；松手（onPressOut）判定按住时长：
  - 小于 300ms：视为误触，cancelListening 直接复位，不等识别；
  - 达到 300ms：stopListening 进入识别，按钮显示"识别中..."。
- 识别结果：normalizeAsrText 归一化 → 非空则写搜索历史并跳转 /pages/home/search?keyword=...；空结果 toast"未能识别到内容"。
- 错误文案映射：权限拒绝 / 模型未安装 / 其他，分别提示可读信息。
- 取消按钮与右上关闭按钮均关闭面板；关闭时复位所有状态。

### 4.5 文本归一化（services/asr/normalize.ts）

针对 Vosk 中文模型的输出做后处理，提升型号可用性：

- 连续 2 个及以上中文数字（含空格分隔）合成阿拉伯数字：六二零五 → 6205，六 二 零 五 → 6205，幺 → 1。单个中文数字不转，避免误伤"三环"等词。
- 斜杠 → /，杠 → -（先斜杠后杠，防"斜杠"内杠被先转）。
- 收敛连续空白为单空格。
- 局限：无法弥补漏识别的字符（Vosk 未识别到的位数补不回来）。

### 4.6 统一弹窗（PrivacyDialog / ConfirmDialog）

背景：Taro showModal 在 RN 端由 Dialog+Mask 双层嵌套 Touchable 实现，Android 真机上"同意"类按钮点击被内层拦截。

- PrivacyDialog：首启隐私同意弹窗，含可点《用户协议》《隐私政策》链接。
- ConfirmDialog：通用确认弹窗，命令式 showConfirmDialog({title, content, confirmText, cancelText, showCancel, confirmColor})，返回 Promise(boolean)；全站 13 处业务弹窗已替换。
- 两者均为 RN 原生 Modal 自绘，视觉同源；H5/小程序继续走 Taro.showModal（无该缺陷）。
- 命令式与组件通过模块级订阅总线通信，含"待显示信号"队列，防御 App 根 componentDidMount 早于子组件 useEffect 注册导致的信号丢失竞态。

## 5. 交互流程

1. 首页点"讲语音"（搜索框麦克风图标或快捷按钮），RN 端打开 VoicePanel；H5/小程序 toast"语音搜索暂仅支持 App 端"。
2. 面板打开即 warmup 预热模型。
3. 按住中央大按钮录音；松手后进入识别。
4. 识别完成归一化文本 → 写入搜索历史 → 跳搜索结果页。
5. 误触（按住不足 300ms）直接复位；空结果/出错按文案提示。

## 7. 模型与 CI/CD

- 模型：vosk-model-small-cn-0.22（约 42MB），放置于 android/app/src/main/assets/model-cn/，Vosk 0.3.3 运行时从 assets 解压加载（目录名必须以 model 开头，gradle genUUID 会为 model* 目录生成 uuid）。
- 本地：scripts/download-vosk-model.ps1 一键下载解压到位（脚本纯 ASCII，规避 PowerShell 5.1 对无 BOM UTF-8 的解析问题）。
- 工程配置：
  - package.json 依赖 react-native-vosk@0.3.3。
  - android/build.gradle rootProject.ext 补充 kotlinVersion（Vosk 库 build.gradle 必需，缺失会构建崩溃）。
  - newArchEnabled=false 下原生桥走旧 bridge，autolinking 自动接入。
- CI：deploy.yml 的 apk job 在 gradle 构建前先下载模型到 assets/model-cn，随 release APK 打包（arm64-v8a / armeabi-v7a 各含模型）。

## 8. 已知局限与后续路线

- Vosk small 模型中文识别弱，轴承型号数字+字母易错、可能漏字；归一化只能修正格式、不能补漏。
- 数字字母混排（如 6205ZZ）与英文品牌（NSK/ SKF）识别不稳，可在后续引入 grammar 热词限定词表（不改输出格式，需配后处理）。
- 后续含金量更高的路线：录音 + 后端云 ASR（讯飞/阿里云 + 型号热词表），仅需新增 CloudProvider 并调整 asr 工厂分支，UI 层零改动；该服务可同时被 H5/小程序复用。
- 如需离线且识别更强，可评估 whisper.cpp 系（需升级 RN/Taro，本期不兼容）。
